# 워크가이드 (가칭) — 내 위치를 아는 AI 오디오 도슨트

> "저 건물 뭐야?" 라고 물으면, 가이드가 바로 대답해 주는 앱.

## 1. 문제 정의

| 기존 방식 | 한계 |
|---|---|
| 가이드 투어 | 재미있지만 비싸고(€20~50), 시간·동선이 고정, 혼자 여행엔 부담 |
| 가이드북 / 구글 검색 | 읽느라 고개를 숙임 → 눈앞의 풍경을 못 봄, 정보 과다 |
| 기존 오디오가이드 앱 (Rick Steves, VoiceMap 등) | 사전 제작된 고정 코스, 코스 밖 건물은 설명 불가, 질문 불가 |

**핵심 인사이트**: 혼자 여행자에게 필요한 건 "정보"가 아니라 *지금 내 눈앞의 것에 대한, 귀로 듣는 이야기*다.

## 2. 제품 컨셉

세 가지 모드를 하나의 경험으로 묶는다.

1. **Ask (질문)** — "오른쪽 건물 뭐야?" → 위치+방향(나침반)으로 대상 특정 → 스토리텔링 답변을 음성으로.
2. **Nearby (자동 안내)** — 걷다가 랜드마크 반경(기본 80m)에 진입하면 먼저 말 걸어줌. "왼쪽 골목으로 가면 ○○ 분수가 있어요."
3. **Route (산책 코스)** — 도시/테마(로마 고대사, 피렌체 르네상스)별 AI 생성 도보 코스 + 턴바이턴 + 설명.

### 핵심 사용 시나리오
- 콜로세움 앞에서 이어폰 착용 → 앱이 "지금 보이는 건 콘스탄티누스 개선문입니다…" 자동 낭독
- 걷다가 "왼쪽 저 성당은?" → 헤딩 기준 좌측 ±45° 장소 후보 → Gemini가 답변
- "여기서 가까운 맛집 말고, 숨은 역사 명소 알려줘" → 테마 필터

### 차별화
- **고정 스크립트가 아닌 생성형**: 코스 밖 어떤 건물도 설명 가능
- **방향 인식**: "오른쪽/왼쪽/정면" 상대 방향 해석 (경쟁 앱에 거의 없음)
- **대화형 + 핸즈프리**: 이어폰만으로 사용, 화면 안 봄
- **페르소나**: 역사학자 / 유머러스 / 아이용 등 톤 선택

## 3. 기술 아키텍처

```
[PWA/모바일]                         [Backend (FastAPI)]                [외부]
 GPS + 나침반(heading)  ─────────▶  /api/nearby   ─────────────▶  Google Places API (New)
 음성입력(STT)          ─────────▶  /api/ask      ─┬──────────▶  Gemini (grounded 답변)
 음성출력(TTS) ◀───────────────────  텍스트 응답    └─▶ 캐시(장소ID+언어+페르소나)
```

- **위치/장소**: Google Places API (Nearby Search New, Place Details) — 장소 후보 + 좌표 + 타입
- **방향 판정**: 사용자 좌표·heading → 각 장소 bearing → 상대각 → 전/후/좌/우 (자체 로직, `app/geo.py`)
- **생성**: Gemini — 장소 메타데이터 + (선택) Wikipedia/Wikidata 요약을 근거(context)로 주고 환각 억제
- **음성**: 1단계 브라우저 Web Speech(무료) → 2단계 Google Cloud TTS / Gemini TTS로 품질 상향
- **캐시**: 같은 장소·언어·페르소나 답변은 재사용 → **LLM 비용의 대부분 절감** (관광지는 반복 질의가 압도적)
- **오프라인**: 도시팩(주요 POI + 사전 생성 해설 + 음성)을 다운로드 → 로밍 데이터 없이 사용

### 핵심 리스크와 대응
| 리스크 | 대응 |
|---|---|
| 환각(잘못된 역사) | 장소 데이터·위키 근거 주입, "모르면 모른다고" 지시, 신고 버튼, 인기 POI는 검수본 |
| 건물 특정 오류(GPS·나침반 오차) | 후보 2~3개 제시 후 확인 질문, 카메라(Gemini Vision) 확인 모드 (3단계) |
| Google 약관/비용 | Places 응답 캐싱 제한 준수(place_id만 장기 저장), 필드 마스크로 비용 절감, 오픈데이터(OSM/Wikidata) 병행 |
| 해외 데이터 요금 | 오프라인 도시팩 |

## 4. 사업화 방향

### 타깃
1순위: **혼자/소규모 자유여행자 (20~40대)**, 유럽·일본 등 역사 밀집 도시. 
2순위: 도시 관광청·박물관 (B2B2C), 시니어 해외여행.

### 수익 모델 (우선순위순)
1. **프리미엄 구독 / 도시팩 판매** — 무료: 도시당 일 N회 질문 + 기본 TTS. 유료: 무제한, 고품질 음성, 오프라인 도시팩. 
   (예: 여행 패스 €4.99/주, €9.99/월, 도시팩 €2.99)
2. **B2B 화이트라벨/API** — 관광청·박물관·호텔 컨시어지에 자사 브랜드 오디오 가이드 제공 (월 구독 + 콘텐츠 제작비). 기존 오디오가이드 기기 대체.
3. **제휴 수익** — 투어/티켓(GetYourGuide, Klook), 근처 식당·카페. *설명의 신뢰를 해치지 않도록 "광고" 명확 표기.*
4. **스폰서 콘텐츠** — 지역 가게의 "숨은 이야기" 코스(명시적 스폰서).

### 단위 경제 (대략)
- 질문 1회 ≈ 입력 ~1.5k + 출력 ~300 토큰 + TTS 약 400자. 캐시 적중 시 거의 0원.
- 여행자 1명/일 20회 가정, 캐시 적중률 60% → 일 약 $0.05~0.15 수준 → 구독가격으로 충분히 마진 확보 가능(실측 필요).

### 검증 로드맵 (돈 쓰기 전 가설 검증)
| 단계 | 기간 | 가설 | 지표 |
|---|---|---|---|
| 0. 셀프 테스트 | 2주 | 내가 걸으면서 쓰고 싶다 | 로마/서울 직접 사용 후기 |
| 1. 지인 베타 (도시 1~2곳) | 1~2개월 | 해설이 가이드만큼 재밌다 | 세션당 질문 수, 재방문 |
| 2. 여행 커뮤니티 배포 | 2~3개월 | 돈 낼 의향 | 유료 전환율 3%+ |
| 3. B2B 파일럿 | 이후 | 관광청이 지갑을 연다 | 계약 1건 |
