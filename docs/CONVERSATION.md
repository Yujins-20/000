# 대화형 해설 설계 (스토리 → 후속 질문)

## 무엇이 문제였나
초기 구현은 **요청마다 독립된 단발 응답**이었다.
- 서버가 이전 대화와 "방금 얘기하던 장소"를 모르므로, 후속 질문("누가 지었어?")에 방향어가 없으면 *가까운 정면 장소를 새로 골라* 같은 해설을 되풀이했다.
- 첫 해설은 4~6문장(20초)이고 근거는 위키 요약 2~3문장뿐이라 내용이 빈약했다.

## 지금 구조
```
클라이언트  ── 질문 + history(최근 8턴) + focus(직전 장소) ──▶  /api/ask/stream  (SSE)
                                                              │ plan_request: 후속? 새 이야기?
                                                              │ build_messages: [system, …history, user]
                                                              ▼ LLM 스트리밍 → 문장 단위로 내려보냄
클라이언트  ◀── meta → sentence* → done ──   문장이 오는 즉시 화면 표시 + TTS 큐에 투입(첫 문장부터 낭독)
```
서버는 **무상태**다. 맥락(history, focus)은 클라이언트가 들고 있다가 매 요청에 실어 보낸다(세션 저장소 불필요, 수평 확장 쉬움).

### 후속 질문 판정 (`plan_request`, `sim.html`의 `plan()`과 같은 규칙)
| 조건 | 처리 |
|---|---|
| focus 있음 + 질문 있음 + **방향어 없음** | **후속 질문**: 같은 장소 유지(위치가 바뀌었으면 최신 거리·방향으로 갱신), 짧게(3~6문장), 이전 말 반복 금지 |
| 방향어 있음("뒤에 뭐 있어?") / 자동 안내(place_id) / focus 없음 | **새 이야기**: 맥락 리셋 |
| 주변에 아무것도 없어도 focus가 있으면 | 후속 질문은 계속 가능(걸어서 멀어졌어도 대화는 유지) |

### 스토리형 첫 해설
10~14문장(약 70~100초). 구성: ① 지금 눈앞 장면(방향·거리) → ② 탄생 이야기(누가·언제·왜) → ③ 일화/반전 1~2개 → ④ 이후의 변화와 지금의 관전 포인트 → ⑤ 주변 연결 → ⑥ "궁금한 걸 물어봐 달라"는 마무리.
- 긴 해설도 **첫 문장이 나오는 즉시 읽기 시작**하도록 문장 스트리밍(`SentenceChunker`)과 TTS 큐(`web/tts.js`)를 쓴다. 너무 짧은 문장은 다음 문장과 합쳐 낭독이 끊기지 않게 한다.
- 처음 소개(캐시 키: 장소·방향·언어·페르소나·깊이)만 캐시하고 후속 질문은 매번 생성한다.
- 후속 질문 추천 칩("누가, 왜 만들었어?" 등)을 응답과 함께 내려준다.

## 위키백과 말고 "모델이 아는 설명"을 쓰는 방법 — `depth`
| depth | 동작 | 장단점 |
|---|---|---|
| `rich` (기본) | [근거]를 뼈대로, 모델의 배경지식(건축·인물·일화·시대상황)으로 살을 붙임. 연도·수치는 **확실할 때만**, 불확실하면 "대략/자료마다 달라요", 전설은 "전해집니다"로 표시, 근거와 충돌하면 근거 우선 | 풍성한 이야기. 단 모델 기억이 틀릴 위험이 있다 |
| `grounded` | [근거]에 있는 사실만 사용 | 정확하지만 빈약 |

앱의 "풍부하게 / 자료만(엄격)" 선택으로 전환한다. **환각 위험은 `rich`의 대가**이므로, 실제 베타에서는 인기 POI의 해설을 사람이 검수한 "골든 스크립트"로 고정하고(캐시에 미리 넣기) 나머지만 `rich`로 생성하는 것을 권한다. 위키 도입부는 문장 경계에서 1,500자까지 근거로 넣는다(기존 3문장).

## API
`POST /api/ask/stream` (SSE) · `POST /api/ask` (일괄) — 공통 요청:
```json
{"lat":41.89,"lng":12.49,"heading":90,"radius_m":150,"question":"누가 지었어?","lang":"ko","persona":"funny",
 "depth":"rich","mode":"auto","place_id":null,
 "history":[{"role":"user","content":"…"},{"role":"assistant","content":"…"}],
 "focus":{"id":"…","name":"…","lat":0,"lng":0,"summary":"…","distance_m":50,"direction":"front"}}
```
SSE 이벤트: `{"type":"meta","mode":"story|followup","place":{…},"follow_ups":[…]}` → `{"type":"sentence","text":"…"}`* → `{"type":"done"}` (실패 시 `{"type":"error"}`).
`history`는 최대 12개·`role`은 user/assistant만 허용(system 주입 차단), 질문 500자 제한.

## 알려진 한계 / 다음 단계
- 카메라(`/api/look`) 이후의 후속 질문은 아직 focus를 만들지 못해 새 이야기로 넘어간다(사진 속 대상 확정 필요).
- history/focus는 클라이언트 메모리라 새로고침하면 사라진다(필요하면 sessionStorage).
- 시뮬레이터의 브라우저-LLM 경로는 스트리밍이 아니라 완성 후 한 번에 표시·낭독한다(서버 경로는 스트리밍).
- AI 엔진이 없으면(mock) 후속 질문에는 "답할 수 없다"고 솔직히 안내한다(답하는 척하지 않음).
- 위키 외 근거 확대: Wikidata/다국어 위키(it, en) 병합, 웹 검색 도구 호출(RAG)은 다음 단계.
